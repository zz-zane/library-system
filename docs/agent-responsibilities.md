# 协作者与工作树职责

## 目的

本文件规定图书管理员系统的协作者职责、工作树映射、分支边界和协作流程。所有角色以 GPT Sol 制定的总体方案、接口契约和验收标准为共同依据。

## 角色映射

| 角色 | 协作者 | 工作树目录 | Git 分支 | 主要职责 |
|------|--------|------------|----------|----------|
| 总设计师 | **GPT Sol** | 主工作树 `D:/project/library-system` | `main` | 需求分析、总体架构、任务拆解与调度、跨模块决策、成果审核和最终整合 |
| 后端工程师 | **GPT Luna** | `D:/project/test/library-system/gpt` | `zz-zane/back_GPT_luna` | FastAPI、SQLAlchemy、Pydantic、认证、数据库、后端 API 及后端自测 |
| 前端工程师 | **Kimi** | `D:/project/test/library-system/great` | `zz-zane/for_kimi` | Vue 3、TypeScript、Element Plus、Pinia、Vue Router、页面与交互实现 |
| 测试工程师 | **DeepSeek** | `D:/project/test/library-system/tester_deepseek` | `zz-zane/tester_deepseek` | 测试计划、pytest 单元与集成测试、缺陷复现、回归验证和质量报告 |

## 职责边界

### GPT Sol：总设计师

- 统一分析需求并确定功能范围、优先级和验收标准。
- 设计整体架构、数据流、模块边界和前后端接口契约。
- 将任务分派给 GPT Luna、Kimi 和 DeepSeek，协调依赖与开发顺序。
- 审核各分支的实现、测试结果及潜在风险。
- 负责跨模块争议决策、成果整合与主分支质量。

### GPT Luna：后端工程师

- 负责 `backend/`、后端依赖及数据库访问层的实现。
- 维护 API 请求与响应模型、错误语义、认证授权和数据一致性。
- 为后端逻辑提供必要的自测，并向 DeepSeek 提供可测试的接口说明。
- 若需改变前端接口契约，先提交给 GPT Sol 决策。

### Kimi：前端工程师

- 负责 `frontend/` 中的页面、组件、路由、状态管理和 API 调用。
- 按既定接口契约处理加载、成功、空状态和错误状态。
- 保证类型检查、构建和关键交互自检通过。
- 若发现接口契约不足或冲突，先反馈给 GPT Sol，不直接改动后端职责范围。

### DeepSeek：测试工程师

- 负责 `tests/` 及测试辅助设施，制定单元、集成和回归测试方案。
- 独立验证前后端成果，记录可复现步骤、预期结果和实际结果。
- 重点覆盖权限、输入边界、异常路径、数据一致性和回归风险。
- 不以修改业务实现来掩盖缺陷；问题应反馈给 GPT Sol 和对应工程师。

## 协作流程

1. GPT Sol 明确需求、接口契约、任务边界和验收标准。
2. GPT Luna 与 Kimi 在各自工作树中并行实现，DeepSeek 同步设计测试。
3. 每个角色只提交职责范围内的改动；跨范围变更须由 GPT Sol 协调。
4. GPT Sol 审核待整合差异，确认接口一致后进行合并或挑选提交。
5. DeepSeek 对整合结果执行测试与回归，提交质量报告。
6. GPT Sol 根据测试结论完成最终验收。

## Git 与工作树约定

- `main` 是整合分支，由 GPT Sol 负责。
- 后端、前端和测试工作分别保留在各自分支，避免直接在 `main` 上并行修改。
- 未经 GPT Sol 审核，不跨工作树修改其他角色负责的模块。
- 合并前必须说明改动范围、验证命令、测试结果和已知限制。
- 项目源码必须先进入 Git 基线，各工作分支同步该基线后再开始并行开发；主工作树中的未跟踪文件不会自动出现在其他工作树中。
